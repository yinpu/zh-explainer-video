# 质量检查

## 自动检查的边界

- 音频非空、有限值、正确采样率、无明显削波。ASR 与规范化讲稿比较，CER > 0.12 时重试，最多两次。数字写法等可能造成假阳性，应核对具体转录。
- 对齐覆盖完整讲稿，时间戳单调且不越界。字幕据此生成，动画锚点取整到视频帧。
- 相邻响度差 > 4 dB、粗略中位音高差 > 4 半音时提出试听提示。这些不是音色相似度评分，中文自然重音可能触发提示。
- 整条母带做 EBU R128 两遍归一化，目标 -18 LUFS、-1.5 dBTP；仅修剪过长边缘静音，连续录音的裁切点先取到视频帧边界，同一录音内的片段接回时保持波形连续；不额外添加固定段间静音。其他模式逐块补到视频帧边界，最终音轨只编码一次。
- 检查时长、尺寸与音视频长度差。默认 300–1200 秒，超出时修改讲稿，不强行改变语速。

## 内容与动画检查

先检查开头是否建立了对主题及其用途的理解，再检查正文是否直接解释对象和机制。来源、版本、发布与复现叙述只有在帮助理解差异或回应任务要求时才应进入正文；不能用机械禁词替代语义审阅。参数应连同含义审阅。

对照 [分镜与视觉论证](storyboarding.md) 和项目 `scenes.md` 检查实际成片，按关键段落记录具体位置与发现：

- 核心结论是否有可见的图形依据和必要推导，开头的问题是否得到回答；从实例推广时，是否解释一般规律成立的理由并保留条件，而非仅凭几个例子下结论。
- 关键洞见是否能定位到具体图形变化，能否说明观众此前的疑问和之后能解释的关系；如安排预测，是否在揭示前留出机会，并在观察依据后给出结论，而非只用高亮或惊叹句宣布洞见。
- 使用反例时，是否指出原推断在哪一步失效，以及修正方法为何有效；例如二分查找的乱序反例应显示被误排除的目标，并解释有序条件如何支持整段排除。
- 新符号和公式项是否能对应到已介绍的对象或量，几何、代数与数值是否一致，同一概念的颜色是否稳定。
- 运动是否表达了变化、对应或因果关系；逐步出现的信息是否足以让观众跟上，是否存在旁白已经得出结论而图形尚未解释的跳步。
- 相连步骤是否保留必要的参照物和对象状态；场景切换是否符合叙事，镜头移动后是否仍能定位正在讨论的关系。
- 关键参数变化和公式变换后是否有观察时间；是否需要同时阅读长文字、追踪多个动作并听取新论点。
- 最终合成画面中的字幕是否遮住图形、公式或标签；缩放、移动及转场中间帧是否仍清楚可读。

这些是观看与内容审阅标准，不由自动 QA 计算风格分数；未观看的片段不能据此标记通过。

不默认添加“图中均为教学示意”等泛泛说明。检查旁白、字幕、画面角标和交付文字；只保留会改变理解的具体假设或近似条件，并放在需要它的位置。不要用删掉数学条件的方式缩短讲解。

检查公式匹配前后是否残留旧对象、动态标签是否跟随图形、镜头移动时标题是否固定，以及 updater 是否在不再需要时清除。公式和中文标题的过渡都要查看中间帧。环境变动后运行 `doctor --verify-render`；构建会逐片校验帧数，帧数失败不可用最终裁切掩盖。

## 实际观看与试听

配音固定为刘飞 0.95 倍，配置见 [固定配音](voices.md)；听感修订复查当前任务的实际问题片段和相邻接缝。QA 的 `pace_checks` 用连续中文对齐窗口筛出局部偏快的位置；中英混读、数字读法和对齐误差都会影响指标，筛查只提供试听位置，不决定通过或不通过。

样片应覆盖关键接缝与转场，长度和数量按工程复杂度确定，可用连续片段或带时间标注的接缝摘录。不要为了满足固定时长或声音段数而刻意拆分旁白。同一录音中的镜头边界不是声音接缝。检查独立录音之间是否换人、语调拔高、语速突变或尾字截断，并判断画面变化是有意的章节转场，还是造成无意的重新开场；保留符合表达意图的停顿。用户反馈的时间点必须包含在修订回归检查中；完整视频的开头、中间、结尾及所有真实录音接缝也应复查。

按公式密度、转场风险和视频长度选择关键动画词进行抽查，目标听感偏差约 200 ms 以内。`rounding_error_ms` 只验证帧取整，不证明对齐模型绝对准确；必须实际对照声音和画面。检查中文缺字、数学符号、单位、标签遮挡、字幕冲突和解释跳步。对照讲稿、字幕和画面的英文术语，保留 token 等标准拼写，不使用“托肯”等发音替代词。试听是否有提问语气、因果与对比重音、推导停顿及自然句意起伏；仅声音平稳或朗读准确不能证明具有课堂讲解的节奏。

不能仅凭全段的平均音高、响度或 ASR 判断接缝听感。新流水线的 `seam_checks` 区分同一录音和独立录音，并记录额外静音与对齐停顿；这些仍不等同于人工听感验收。

没有实际试听时，标记 `listening_review: pending`，不要把 ASR 正确当作音色合格。未观看的画面也保持 pending。

实际完成检查后，可在项目根目录保存 `review.json`，仅填写真正完成的项：

```json
{
  "video_sha256": "实际被检查视频的 SHA-256",
  "listening_review": "pending",
  "visual_review": "passed",
  "notes": "具体检查方式、范围、检查人和发现"
}
```

QA 仅在视频指纹一致时采用此记录。修改视频后需要重新检查；发现问题填 `needs_revision` 并列出具体位置。音色异常重做完整语义块，并复查相邻接缝。
